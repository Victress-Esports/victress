# Pilot readiness checklist (infrastructure and operations)

Created 2026-11-07. This is the short operational list that has to be true before the first design partner signs up. It does not replace the legal and safety gates; those stay in their own documents and are linked below. Nothing here is a claim that an item is done.

## Required before the first design partner signs up
- [ ] **Upgrade Supabase to Pro before the first design partner signs up.** Production is on the Free plan, which has no backups and no point in time recovery (verified 2026-11-07: organization plan "free"; Supabase documents daily backups for Pro, Team and Enterprise only). The founder accepted this for the empty database only (override on 2026-11-07 to apply the privacy expand migration with 0 users). Once any real data exists, that acceptance no longer applies. Decide at the same time whether the point in time recovery add-on is needed, and take a manual export before the first sign up whatever the plan.
- [ ] **Use a separate Supabase project for Preview deployments.** Per the founder (2026-11-07), Preview deployments currently share the production Supabase project and the production service role key; the repository contains no Vercel configuration, so this cannot be confirmed from the code. Every pull request preview, including unreviewed drafts, therefore runs code against production data with a key that bypasses row level security. That is tolerable only while the database is empty. Before the first sign up: create a second Supabase project (same migrations, its own keys), scope its URL, anon key and service role key to the Preview environment in Vercel and keep the production values on Production only, and confirm a preview cannot reach production data. Needs the founder to change Vercel and Supabase settings; not done.
- [ ] **Rate limiting and invite code entropy for `team_invite_info` and `join_team`.** Invite codes today are 12 hex characters (48 bits) and both functions can be called directly through the public API with no throttle. Proposal: [team-invite-rate-limiting.md](team-invite-rate-limiting.md). Changing the code length is free now because no team exists; it gets harder with real teams. Longer codes (130 bits) were applied 2026-11-07 (migration `longer_invite_codes`, version `20261107060917`); throttling and the server side lookup are still open.
- [ ] **Revoke public execute on `rls_auto_enable()`.** A platform provisioned security definer function that anon and signed in users can call through the REST API. Dry run done and rolled back, rollback written, not applied: [rls-auto-enable-revoke.md](rls-auto-enable-revoke.md). Needs its own authorization.
- [x] Privacy foundation: expand, switch and contract applied 2026-11-07 with 0 profiles and 0 auth users each time ([privacy-rollout.md](privacy-rollout.md), rollbacks: [expand](privacy-expand-rollback.md), [contract](privacy-contract-rollback.md)). Re-verify after any later migration.
- [ ] Sign in state in production verified (open or closed) and sign in tested end to end.
- [ ] Legal text and the data practices it describes reviewed by counsel; contact form notice wording; partner agreement.
- [ ] Trust and Safety owner, deputy, coverage and report channel in place: [safety-operations.md](safety-operations.md), decision 5 in [decision-register.md](decision-register.md).
- [ ] Consent control built and approved before any analytics is enabled (separate PR, blocked).
- [ ] Scrim uploads stay off until formally approved; `20261107000300_dashboard_foundation.sql` is not applied to production before then ([privacy-rollout.md](privacy-rollout.md)).
